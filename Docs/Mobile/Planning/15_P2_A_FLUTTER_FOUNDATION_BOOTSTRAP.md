version even though the foundation adds no native plugins.

Tools 36.0.0, uses JDK 17 and builds the development debug flavor. Flutter
action and setup-action major tags remain subject to repository CI policy; the
runtime and Android SDK package versions themselves are explicit.

## Implemented scope

- Android-only Flutter project under `retailpos-mobile/`.
- App bootstrap, Riverpod provider composition, GoRouter routes and distinct
  development/staging Android flavors.
- Feature-first `domain`, `application`, `infrastructure` and `presentation`
  boundaries for the foundation capability-status feature.
- Environment parsing with explicit rejection of unknown values.
- Typed success/failure result and failure types.
- Safe logging abstraction that accepts only an allow-listed event enum; no
  user, token, request or business data can be passed to the logger.
- Dio provider configured with timeouts but no ERP base URL, credentials,
  interceptors or request call sites.
- Neutral placeholder screens only. No authentication, token storage,
  business API, Drift database/tables, catalogue, stock take, logo or Figma
  recreation.
- Import-boundary, environment, result and widget/navigation tests.

## Known limitations and next gate

- No release signing configuration exists; CI validates a debug APK only.
- Authentication, token lifecycle, business/outlet context and authorization
  remain gated by their approved ADRs.
- No ERP calls or business data are implemented.
- Brand assets and Gold/Brown/Ivory UI tokens remain pending explicit
  confirmation; this slice uses neutral framework styling.
- P2-B must wait for review of this foundation and its validation results.
